# Модель 04: Logistic Regression + RuBERT (finetuned)

## Описание
Четвёртая модель для классификации тендеров на два класса:
- `supply` — поставка товаров
- `work` — выполнение работ или услуг

Это **гибридная модель с дообучением**: текст сначала проходит через **дообученный RuBERT**, который превращает его в вектор чисел (эмбеддинг), а затем этот вектор подаётся в **логистическую регрессию** для финальной классификации.

**Ключевое отличие от модели 03:** RuBERT был **дополнительно обучен** на наших данных (11 523 размеченных тендера).

---

## Что такое дообучение (finetuning)?

Дообучение — это процесс, при котором мы берём уже обученную нейросеть (RuBERT) и продолжаем обучать её на наших данных.

| Без дообучения (03) | С дообучением (04) |
|---------------------|---------------------|
| RuBERT используется «как есть» | RuBERT дополнительно обучается на наших данных |
| Веса модели не меняются | Веса модели обновляются под нашу задачу |
| Модель знает только общий русский язык | Модель адаптируется под тендерную лексику |

---

## Как работает модель
Текст → Дообученный RuBERT (768 чисел) → Logistic Regression → Класс (supply/work)

### Как проходит дообучение

1. **Загружаем готовый RuBERT** — модель уже обучена на миллиардах текстов.
2. **Подаём наши данные** — 11 523 пары (текст, метка).
3. **Модель делает предсказание** — вычисляет вероятность `work` или `supply`.
4. **Сравниваем с правильным ответом** — считаем ошибку (loss).
5. **Обновляем веса** — модель «учится» на своих ошибках.
6. **Повторяем 5 раз** (5 эпох).

В результате модель адаптируется под тендерную лексику и лучше разделяет классы.

### Шаг 1: Дообучение RuBERT
- Берём готовый RuBERT от DeepPavlov
- Обучаем его на 11 523 размеченных тендерах (5 эпох)
- Модель адаптируется под тендерную лексику

### Шаг 2: Текст → эмбеддинг
- Текст подаётся в дообученный RuBERT
- На выходе — вектор размером **768** чисел

### Шаг 3: Эмбеддинг → класс (Logistic Regression)
- Вектор из 768 чисел подаётся в логистическую регрессию
- LR находит линейную границу и выдаёт класс

### RuBERT vs TF‑IDF

**TF‑IDF** — это математический метод, который превращает текст в вектор чисел на основе частоты слов. Он быстрый и интерпретируемый, но не понимает смысл текста.

**RuBERT** — это нейросеть, которая превращает текст в вектор чисел на основе смысла. Она понимает контекст и порядок слов, но требует больше ресурсов.

| | TF‑IDF | RuBERT |
|---|--------|--------|
| **Что в векторе** | Частота слов | Смысл текста |
| **Понимает контекст** | ❌ Нет | ✅ Да |
| **Скорость** | Быстро | Медленнее |
| **Интерпретируемость** | Высокая | Низкая |

## Как считаются метрики

Все метрики считаются на тестовой выборке (20% данных, 2305 записей).

| Метрика | Формула | Что показывает |
|---------|---------|----------------|
| **Accuracy** | (TP+TN)/(TP+TN+FP+FN) | Доля правильных ответов |
| **Precision** | TP/(TP+FP) | Точность предсказаний `supply` |
| **Recall** | TP/(TP+FN) | Полнота — сколько реальных `supply` найдено |
| **F1‑Score** | 2*P*R/(P+R) | Баланс точности и полноты (главная метрика) |
| **ROC‑AUC** | Площадь под ROC‑кривой | Способность разделять классы |

## Почему дообучение не дало прироста?

| Причина | Объяснение |
|---------|------------|
| **1. RuBERT уже сильный** | Базовый RuBERT обучен на миллиардах текстов и уже знает русский язык |
| **2. Мало данных** | 11 523 примера — недостаточно для значимого улучшения |
| **3. Тексты короткие** | Названия тендеров не дают сложных контекстов для дообучения |
